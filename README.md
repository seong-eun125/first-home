# FIRST HOME — AI 기반 첫 자취 통합 관리 플랫폼

> 처음 혼자 집을 구하는 사람이 **현장에서 놓치지 않고, 내 기준으로 고르고, 고른 집의 정보 그대로 입주까지 이어 가도록** 돕는 웹 서비스

| 항목 | 내용 |
|---|---|
| 구분 | 인공지능 프로젝트 개인 과목 프로젝트 |
| 형태 | 웹 서비스 (데스크톱 + 모바일 브라우저 대응) |
| 스택 | React · TypeScript · Vite · Tailwind CSS · shadcn/ui / FastAPI · SQLAlchemy · Alembic / MySQL 8.0(개발) · TiDB Cloud(배포) / OpenAI API / 국토교통부 실거래가 오픈API |
| 배포 | **https://firsthome-hzi4.onrender.com** (Render + TiDB Cloud, `main`에 push하면 자동 배포) |
| 상태 | 핵심 흐름(기준 설정 → AI 매물 판정 → 현장 체크 → 점수·비교 → AI 리포트 → 결정 → 입주 준비) 실제 동작 · 웹 배포 · 사용자 만족도 설문 진행 중 |

---

## 1. 해결하려는 문제

첫 자취를 준비하는 사람은 정보가 없는 게 아니라 **정보를 정리하고 판단하는 기준이 없어서** 실수합니다.

- **현장에서 놓친다** — 집을 보는 10~15분 동안 수압, 곰팡이, 방음, 채광 같은 항목을 빠뜨리고, 돌아와서야 "그거 확인했었나?"를 떠올립니다.
- **비교가 안 된다** — 3~5곳을 보고 나면 사진·메모·기억이 섞여, 어떤 집이 왜 좋았는지 말로 설명하기 어렵습니다.
- **내 기준이 없다** — 같은 집도 야간 근무자와 재택 근무자에게 평가가 다릅니다. 인터넷의 "좋은 집 고르는 법"은 나에게 맞춰져 있지 않습니다.
- **계약 이후가 끊긴다** — 집을 정한 뒤 계약 확인, 전입신고, 초기 비용, 필수템 준비를 다시 처음부터 찾아야 합니다.
- **보증금 위험을 모른다** — 전세사기 예방 수칙이 있다는 것 자체를 모르는 경우가 많습니다.

**FIRST HOME의 접근:** 기록과 점수 계산은 정확해야 하므로 **백엔드 규칙**이 맡고, 흩어진 기록을 사람이 이해할 수 있는 판단 근거와 다음 행동으로 바꾸는 일은 **생성형 AI**가 맡습니다.

## 2. 프로젝트 목적

1. 집을 보는 순간의 기록을 **빠짐없이, 구조화된 형태로** 남기게 한다.
2. 사용자의 생활 패턴으로 만든 **개인 가중치**로 매물을 점수화하고, 기준을 바꾸면 순위가 즉시 바뀌는 것을 보여 준다.
3. 생성형 AI가 기록을 근거로 **장단점·확인하지 못한 점·물어볼 질문·조건별 추천**을 정리해, 사용자가 스스로 결정하도록 돕는다.
4. 결정한 집의 정보를 그대로 이어받아 **계약·이사·입주·정착**까지 한 곳에서 관리한다.
5. 공공데이터(국토교통부 실거래가)로 **시세 대비 비싼지**를 객관적으로 확인하게 한다.

## 3. 예상 사용자와 활용 상황

| 사용자 | 상황 | FIRST HOME에서 하는 일 |
|---|---|---|
| 처음 자취하는 대학생 | 학교 근처 원룸 3~4곳을 하루에 몰아서 봄 | 휴대폰으로 현장 체크, 저녁에 비교·AI 리포트 확인 |
| 사회초년생 | 회사 근처로 이사, 퇴근 후 저녁에만 집을 볼 수 있음 | '저녁 재방문' 안내, 소음·치안 가중치 높게 설정 |
| 재택·야간 근무자 | 낮에 자야 해서 방음·암막이 중요 | 생활 패턴 → 방음·채광 가중치 자동 반영 |
| 부모님과 함께 결정하는 학생 | 본 집을 가족에게 설명해야 함 | 비교 결과 인쇄·PDF, AI 비교 리포트 공유 |
| 계약을 앞둔 사용자 | 보증금이 걱정되고 무엇을 확인할지 모름 | 보증금 지키기 가이드(3·3·3법칙), 계약서 금액 대조, 실거래 시세 비교 |

## 4. 사용자가 필요로 하는 기능

- 내 생활 패턴과 우선순위를 한 번 입력하면 **모든 매물에 같은 기준**이 적용될 것
- 현장에서 **빠르게 누르기만 하면 되는** 체크리스트 (확인 못한 항목은 '확인 못함'으로 따로 표시)
- 사진·메모를 **체크 항목에 붙여** 나중에 근거로 다시 볼 수 있을 것
- 여러 집을 **같은 항목끼리** 나란히 비교, 차이 나는 부분만 보기
- "그래서 어떤 집이 나에게 맞는지"를 **근거와 함께** 설명해 주는 요약
- 시세 대비 **비싼지 싼지** 객관적으로 확인
- 결정 후 **할 일·비용·필수템**을 다시 입력하지 않고 바로 관리

## 5. 핵심 기능

| # | 기능 | 설명 | 생성형 AI |
|---|---|---|---|
| 1 | **내 기준 설정 (온보딩)** | 생활 패턴·예산·절대 조건 5단계 질문 → 카테고리 가중치(1~5) 자동 계산, 직접 조정 | 사용 안 함 (규칙) |
| 2 | **현장 체크리스트** | 필수 14 + 선택 17개 항목, 좋음/보통/나쁨/확인 못함, 메모·사진, 자동 저장, 모바일 최적화 | 사용 안 함 (규칙) |
| 3 | **적합도·확인도 점수와 비교** | 가중 평균 적합도, 필수 항목 확인 비율, 절대 조건 위반 표시. 가중치 슬라이더를 움직이면 순위가 즉시 재계산 | 사용 안 함 (규칙) |
| 4 | **AI 매물 리포트** ★ | 한 집의 기록을 장점·단점·확인하지 못한 점·중개사에게 물어볼 질문으로 정리. 모든 문장에 근거 항목 칩 | **사용** |

| 5 | **AI 비교 리포트** ★ | 여러 집을 "채광을 가장 중요하게 본다면 A, 통학이 우선이면 B"처럼 조건별로 추천, 결정 전 확인할 것 | **사용** |
| 6 | **동네 실거래 시세 비교** | 국토교통부 전월세 실거래가로 같은 지역·유형·면적 거래와 내 월세를 비교 (낮은 편/비슷한 편/높은 편) | 사용 안 함 (규칙) · AI 요약 확장 예정 |
| 7 | **결정 이후 입주 준비** | '이 집으로 결정' → 입주일 기준 할 일, 초기 비용·월 고정비, 계약서 금액 대조, 자취 필수템, 정착 안내 자동 생성 | 사용 안 함 (규칙) |
| 8 | **보증금 지키기 가이드** | 국토교통부 안심계약 3·3·3법칙, 위험 신호, 공식 사이트 링크 | 사용 안 함 (정적 안내) |

## 6. 각 기능에서 생성형 AI가 하는 역할

**원칙: AI는 점수를 정하지 않는다.** 점수·순위·시세 판정은 모두 백엔드 규칙으로 계산하고, AI는 이미 계산된 결과와 실제 기록을 **해석하고 설명하는 역할**만 맡습니다.

| 기능 | AI가 하는 일 | AI가 하지 않는 일 |
|---|---|---|
| AI 매물 리포트 | 체크 결과·메모·점수를 읽고 장점/단점/미확인/질문을 자연어로 요약, 각 문장에 근거 항목 id 부착 | 점수 계산, 기록에 없는 사실 추측 (근거 id가 실제 기록이 아니면 백엔드가 문장을 삭제) |
| AI 매물 판정 | 캡처 이미지·광고 글에서 금액·층·옵션을 추출(근거 문구 포함), 우선순위별 평가, 판정 의견·질문·현장 확인 목록 작성 | 근거 문구가 원문에 없는 숫자 사용(백엔드가 버림), 예산·절대 조건 무시 (규칙이 판정 상한을 정함) |
| AI 비교 리포트 | 가중치와 카테고리 점수 차이를 해석해 조건별 추천 문장 생성, 결정 전 확인 목록 작성 | 최종 선택 강요, 순위 변경 |
| (예정) 실거래 시세 요약 | 계산된 중앙값·백분위를 쉬운 문장으로 설명 | 시세 판정 (규칙이 계산) |
| (예정) 매물 글 자동 입력 | 매물 광고·중개사 문자에서 보증금·월세·관리비·옵션 추출 → 폼 채움 (사용자 확인 후 저장) | 사용자 확인 없이 저장 |

**안전장치**
- API 키는 FastAPI 서버의 환경변수(`.env`)에만 존재 — 프론트엔드·GitHub에 노출되지 않음
- 이름·이메일·사진은 AI에 보내지 않음, 메모는 항목당 200자 제한
- 같은 입력은 SHA-256 해시로 캐시해 재호출하지 않음, 사용자별·전체 하루 호출 한도
- 키가 없거나 호출이 실패하면 **규칙 기반 응답**으로 대체하고 화면 배지로 명확히 구분

## 7. 동작 과정 (입력 → 처리 → 출력)

| 기능 | 입력 | 처리 | 출력 |
|---|---|---|---|
| 내 기준 설정 | 생활 패턴·예산·절대 조건 답변 | 규칙으로 카테고리 가중치 계산 → DB 저장 | 가중치 1~5 (슬라이더로 조정 가능) |
| 현장 체크 | 항목별 좋음/보통/나쁨/확인 못함, 메모, 사진 | 값 검증, 사진 위치정보(EXIF) 제거, 자동 저장 | 체크 기록, 미확인 항목 목록 |
| 점수·비교 | 체크 기록 + 가중치 | 항목 점수(1/0.5/0) → 카테고리 평균 → 가중 평균, 확인도·절대 조건 검사 | 적합도·확인도·순위, 비교표 |
| AI 매물 리포트 | 점수 결과 + 체크 기록 (개인정보 제외) | 캐시 확인 → OpenAI 호출(JSON 응답) → 근거 id 검증 | 장점·단점·미확인·질문 + 근거 칩 |
| AI 매물 판정 | 캡처 이미지(최대 3장) / 링크 / 광고 글 + 내 조건 | 이미지 메타데이터 제거·축소, 링크는 내부망 차단 후 1회 수집 → OpenAI(이미지 입력) → 근거 검증 → 예산·절대 조건·위험 표현·실거래 시세 규칙 검사 | 최종 판정(AI 의견 + 규칙), 읽은 정보, 우선순위별 평가, 질문, 등록 폼 미리 채움 |
| AI 비교 리포트 | 비교 대상 점수·차이 항목 + 가중치 | 캐시 확인 → OpenAI 호출 → 근거 검증 | 조건별 추천, 결정 전 확인 목록 |
| 실거래 시세 | 지역 코드·주택 유형·(동) + 내 매물 보증금·월세·면적 | 국토교통부 API 6개월 조회(캐시) → 면적·보증금 필터 → 백분위 계산 | 시세 판정, 중앙값, 최근 거래 목록 |
| 입주 준비 | 결정한 매물 + 입주일 | 템플릿으로 할 일·비용·필수템 생성 | 일정별 할 일, 예산 비교, 구매 체크 |

디자인 원칙: 딥그린(#2F5D50)·세이지·화이트 중심, 넉넉한 여백과 둥근 카드, 귀엽거나 관리자 템플릿처럼 보이지 않게.

## 10. 생성형 AI 활용 방안

**현재 구현**
- AI 매물 판정 (캡처·링크·광고 글 → 내 조건 기준 판정, 이미지 인식)
- AI 매물 리포트, AI 비교 리포트 (근거 기반 요약, 근거 없는 문장 자동 제거)

**확장 계획 (비용 대비 효과 순)**
1. ~~매물 광고 붙여넣기 → 등록 폼 자동 입력~~ → AI 매물 판정으로 구현 완료
2. 실거래 시세 결과를 쉬운 말로 요약 (데이터 근거가 있어 지어낼 위험 낮음)
3. 현장 음성 메모 → 체크리스트 자동 기록 (음성 인식 + 항목 분류)
4. 미확인 항목 기반 집주인·중개사 질문 문자 초안
5. 사진 참고 분석 (곰팡이·누수 흔적 의심 표시, 점수에는 반영하지 않음)
6. 계약서 특약 쉬운 말 설명 (법률 자문 아님 고지)

**비용 관리:** 버튼을 누를 때만 호출 · 입력 해시 캐시 · 경량 모델 · 출력 토큰 상한 · 하루 호출 한도 · 리허설용 `AI_MODE=mock`

MySQL이 켜져 있는 상태에서, 프로젝트 폴더의 `backend` 폴더로 이동해 실행합니다.

```bash
cd backend
mysql -u root -p < setup_db.sql
```
root 비밀번호를 입력하면 `firsthome`(서비스용), `firsthome_test`(테스트용) DB와 `firsthome` 사용자가 만들어집니다.
MySQL Workbench를 쓴다면 `setup_db.sql` 내용을 붙여 넣고 실행해도 됩니다.

> Docker를 쓰고 싶다면(선택): 프로젝트 최상위 폴더에서 `docker compose up -d` 한 번이면 같은 DB가 준비됩니다.

### 2-3. 백엔드 설치

**Windows (PowerShell)**
```powershell
cd backend
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

**macOS / Linux**

`.env` 파일을 열어 `JWT_SECRET`을 아무 긴 문자열로 바꾸세요. MySQL 비밀번호를 다르게 만들었다면 `DATABASE_URL`도 고칩니다.

## 4. OpenAI API 키 연결

1. `backend/.env`에 **키만** 넣으면 됩니다 (프론트엔드 코드나 GitHub에는 절대 넣지 마세요. `.env`는 `.gitignore`로 제외되어 있습니다).
   ```
   OPENAI_API_KEY=발급받은키
   OPENAI_MODEL=
   ```
   `OPENAI_MODEL`을 비워 두면 서버가 이 키로 쓸 수 있는 모델 목록을 조회해 가벼운 모델을 자동으로 고릅니다 (gpt-4.1-mini → gpt-4o-mini → … 순, 모두 이미지 입력 가능). 고른 모델이 이 키에서 막혀 있으면 다음 후보로 자동으로 넘어갑니다.
2. 연결을 확인합니다 (가상환경, backend 폴더).
   ```bash
   python -m app.ai_check            # 모델 자동 선택 + 짧은 테스트 호출
   python -m app.ai_check --models   # (선택) 후보 모델 목록 보기
   ```
3. 백엔드를 다시 시작합니다. `/api/health`의 `ai_mode`가 `openai`로 바뀌면 연결된 것입니다. 실제로 쓰는 모델 이름은 AI 리포트 배지에 표시됩니다.

**비용을 줄이는 장치 (이미 적용됨)**
- 매물 등록·체크·점수 계산·비교·슬라이더 조작에는 AI를 부르지 않습니다. '분석하기'·'AI 비교 리포트' 버튼을 누를 때만 호출합니다.
- 입력 데이터가 같으면 저장된 결과를 다시 씁니다 (같은 매물을 여러 번 눌러도 재호출 없음).
- 사진은 보내지 않고, 메모는 항목당 200자까지만 보냅니다. 이름·이메일도 보내지 않습니다.
- 사용자별 하루 30회, 전체 하루 300회 한도 (`.env`에서 조정). 넘으면 규칙 기반 응답으로 대체합니다.
- 출력 토큰 상한 1500 (`AI_MAX_OUTPUT_TOKENS`).
- 시연 리허설 때는 `AI_MODE=mock`으로 두면 비용이 0입니다.

**AI가 점수를 정하지 않도록 한 방법:** 점수는 `backend/app/services/scoring.py`의 규칙으로만 계산합니다. AI에는 계산된 점수와 실제 기록을 보내고, AI가 쓴 장단점마다 근거 항목 id를 달게 한 뒤, 실제로 기록된 항목이 아닌 근거를 단 문장은 백엔드가 버립니다.

## 5. 문제가 생겼을 때

| 증상 | 확인할 것 |
|---|---|
| 브라우저에 '서버에 연결하지 못했습니다' | 터미널 1에서 uvicorn이 실행 중인지, http://localhost:8000/api/health 가 열리는지 |
| health가 `"db":"error"` | MySQL이 켜져 있는지, `.env`의 `DATABASE_URL` 사용자·비밀번호·DB 이름 |
| `Access denied for user 'firsthome'` | `setup_db.sql`을 실행했는지, 비밀번호가 `.env`와 같은지 |
| `Table ... doesn't exist` | `alembic upgrade head`를 실행했는지 |
| 데모 계정 로그인 실패 | `python -m app.seed --demo` 실행 여부 |
| `'uvicorn'은(는) 내부 또는 외부 명령...` | 가상환경이 켜졌는지 (`.venv\Scripts\activate`) |
| `npm run dev` 오류 | `frontend` 폴더에서 `npm install`을 했는지, Node 버전 20 이상인지 |
| 포트 사용 중 (8000 / 5173) | 이미 켜진 서버를 끄거나, 터미널을 닫고 다시 실행 |
| AI 리포트에 '호출 실패' 배지 | 리포트 아래 '원인' 문구 확인 → 키·모델명·한도 확인. 서비스는 대체 응답으로 계속 동작 |
| 사진 업로드 실패 | JPG·PNG·WEBP, 8MB 이하인지 |

자동 테스트로 백엔드 전체 흐름을 확인할 수 있습니다 (가상환경에서, `backend` 폴더):
```bash
python -m pytest -q
```
`31 passed`가 나오면 정상입니다. 테스트는 `firsthome_test` DB만 사용합니다.

> shadcn/ui 컴포넌트는 shadcn CLI 대신 같은 방식(Radix UI + Tailwind 소스 파일)으로 `src/components/ui/`에 직접 넣었습니다. 작업 환경에서 shadcn 레지스트리 사이트에 접속할 수 없었기 때문이며, 사용 방법은 동일합니다.

## 7. DB 테이블 (17개, 사진은 photos.data에 저장)

`survey_responses`(만족도 설문) · `market_cache`(실거래가 응답 캐시) · `home_items`(필수템 구매 목록) · `users` · `user_profiles`(생활 패턴·예산·절대 조건) · `priority_weights`(카테고리 가중치) · `checklist_items`(체크 항목 마스터) · `listings`(매물) · `listing_visits`(방문 기록) · `listing_checks`(체크 결과) · `photos` · `comparisons`(비교 실행 기록) · `ai_reports`(AI 결과·캐시) · `ai_usage_logs`(AI 사용량) · `homes`(최종 선택) · `home_tasks`(할 일) · `home_costs`(비용)

## 8. 동네 실거래 시세 (국토교통부 전월세 실거래가)

매물 상세 화면의 **동네 실거래 시세** 카드에서 최근 N개월 신고된 전월세 거래와 이 집 월세를 비교합니다.

- 사용 API (공공데이터포털, 무료): 단독/다가구 · 연립다세대 · 오피스텔 **전월세 실거래가 자료**
- 키 위치: `backend/.env` 의 `MOLIT_API_KEY` (프론트엔드·GitHub에 노출 금지)
- 키가 없으면 화면에 **예시 데이터**라고 표시된 가짜 숫자로 동작합니다.
- 같은 지역·월 응답은 `market_cache` 테이블에 저장해 다시 호출하지 않습니다 (최근 2개월 12시간, 그 이전 30일).
- 판정(낮은 편/비슷한 편/높은 편)은 비슷한 보증금 거래 중 월세 백분위로 계산하는 규칙입니다. AI가 정하지 않습니다.
- 키 점검: `python -m app.molit_check` (기본: 서울 구로구 오피스텔 지난달)


## 9. 배포 (한 서버로 화면 + API)

`frontend/dist`(빌드 결과)가 있으면 FastAPI가 화면까지 함께 제공합니다. 같은 주소라서 로그인 쿠키와 CORS 설정이 단순합니다.

- **Docker 이미지:** 저장소 최상위의 `Dockerfile`이 프론트 빌드 → 백엔드 설치 → 시작 시 `alembic upgrade head` → 서버 실행까지 처리합니다.
- **호스팅 환경변수:** `backend/.env.example` 맨 아래 '배포 서버에서 설정할 값'을 참고하세요.
  - `APP_ENV=production`이면 32자 이상의 `JWT_SECRET`이 없을 때 서버가 시작되지 않습니다 (토큰 위조 방지).
  - `COOKIE_SECURE=true`이면 https에서만 로그인 쿠키를 보냅니다.
  - `DB_SSL=true`이면 클라우드 MySQL에 인증서 검증된 암호화 연결을 씁니다.
- **관리자 화면:** `ADMIN_EMAILS`에 넣은 이메일로 가입·로그인하면 `/admin`(운영 현황)과 `/survey/results`(설문 결과)만 보입니다. 관리자·데모 계정의 응답과 사용 기록은 집계에서 제외되고, 응답 원자료는 CSV로 내려받습니다.
- **데이터 보존:** 설문 응답·매물·사진은 모두 외부 DB(TiDB)에 저장되므로 서버가 잠들거나 재배포돼도 사라지지 않습니다.
- **현장 사진:** 무료 호스팅은 서버 디스크가 재시작 때마다 지워지므로, 사진은 위치정보를 지운 JPEG로 **DB에 저장**합니다.
- **추천 구성 (무료):** Render(웹 서버, `render.yaml` Blueprint) + TiDB Cloud Starter(MySQL 호환 DB, SSL 필수 → `DB_SSL=true`).
  - Render 무료 서버는 15분 동안 접속이 없으면 잠들고, 다음 접속 때 깨어나는 데 약 1분이 걸립니다.
  - `main` 브랜치에 push하면 자동으로 다시 배포됩니다.
- **클라우드 DB 연결 점검:** `DATABASE_URL='mysql://...' DB_SSL=true python -m app.db_check` (비밀번호는 출력하지 않음)
